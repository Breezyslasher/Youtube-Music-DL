Upgrade revisits tracks whose .lrc has no per-word timing, and tracks whose word timing jumps backwards mid-line, and replaces the sidecar only where Apple has a good word-level version - the one pass that overwrites an existing sidecar, and only ever with the richer form of the same lyrics. Needs an Apple token.

Apple times syllables, not words, and until v0.48.0 we put a space between every one of them - so "Tumble out of bed" was written as "Tum ble out of bed". Nothing in a finished .lrc says where the word breaks were, so a sound file cannot be told from a spoiled one: this fetches every word-by-word sidecar again and writes it correctly. Only worth running once, on a library built before v0.48.0. Nothing is deleted: a sidecar is replaced in place, and one Apple cannot answer for now is left exactly as it was and queued for review above if the fault was a refused match. Needs an Apple token.

No FLAC or WAV: the source tops out around 160 kbps Opus / 256 kbps AAC, so a lossless container would only be a bigger file that misreports its own quality.

Apple has the best coverage of the three, including older catalogue the others miss, and is the only source with per-word timing. It needs the media-user-token of a signed-in account with an active subscription (browser devtools → any amp-api request → the Media-User-Token header). The token is long-lived but not permanent - signing out, a password change or a lapsed subscription invalidates it - so test it here if Apple stops returning lyrics.
